# ToneRelay 0.8.0.0

## 多轮修图复用工作副本

普通修图首次建立工作虚拟副本，此后在同一 UUID 上继续调整。
忘记 UUID 时，结合 TRLR 名称、原片关联、当前 Catalog 和操作记录找回；
不能只凭副本名称或最大的版本号认定目标。明确要求独立方案时仍可另建副本。

名称包含保护、锁定、勿改、只读、留档，或对应独立英文保护标记的副本，
会在 Runtime 与 Lightroom 实际写入前受到检查。名称进入并发校验 token，
显影参数与原生蒙版共享保护规则；只读查看仍可使用。

## 预览与对话展示

返回图片的 MCP 工具新增可选 display，默认 false。模型内部迭代、批量看片和
打分继续获得原生图片内容，但不会额外生成 image-delivery 展示副本。
普通对话看图与最终交付使用 display=true，客户端可继续引用本地展示图片。
已完成的参数操作可从保存的结果补交展示图片，无需再次修改或渲染。

这次没有实现端到端纯内存传输。Lightroom 渲染、Bridge 与历史工件仍可能落盘，
不同客户端的图片展示能力仍须在实际会话核验。

## 更新与验证

Runtime、MCP 与 Lightroom 插件版本统一为 0.8.0.0；
Codex 客户端插件清单按标准 SemVer 表示为 0.8.0+build.0。
Lightroom build 为 poll-lifecycle-0.8.0.0。更新时统一使用同一固定提交，
并一起更新 Lightroom 插件。缺少 copy_protection_v1 能力的旧插件会被拒绝原地写入。

本轮通过隔离环境中的 Runtime、MCP 协议和 Lua SDK 替身回归验证。
发布源码没有切换本机运行环境，也没有以真实 Catalog 写入代替用户后续更新验收。
现有照片、副本、配置与缓存保留策略不随本次发布自动迁移。
